## 3. 【最重要項目】欠落の物理的表現

仕様書 5 の「他の全ての装飾を削っても、これだけは実装してください」に対する回答。

**損傷は装飾ではなく、原稿データの一部として指定されている。**
本文中に損傷の種別を書き込む記法（`[[s|…]]` 掻き取り、`[[w|…]]` 水損、
`[[b|…]]` 焼け、`[[x|…]]` 滅失）を設け、
**どの語が失われるかを、文章を書くのと同じ操作で決めている。**
損傷を後から画面上で「置く」作業は一度も発生していない。

### 損傷と物語の対応

| 丁 | 箇所 | 損傷 | 何が失われているか |
|---|---|---|---|
| 5 | 人物一覧の筆頭 | 掻き取り | **その人の名**。記録者が自ら削った（27丁に理由が書かれる） |
| 8–12 | 第一幕 | **ほぼ無傷** | まだ何も欠けていない |
| 13 | 「そのあとに欠けたものは…」 | 掻き取り | 欠けたものの内容。書いても本人には読めない |
| 13 | 小口の数取り | 後半6本が薄い | 死んだ回数。数が合わなくなる |
| 16 | 「空が低く、水が黒く…」 | 水損 | コールドハーバーの描写 |
| 18 | 「わたしの名を一度まちがえた」 | 水損 | 記録者の名を忘れはじめる場面 |
| 19–20 | 同一の葉の表裏 | **焼け（本書唯一）** | 不死の申し出を拒み、書物を燃やす場面。余白に「火の粉が飛んだ」 |
| 21–27 | 綴じを貫く二つの穴 | 虫損 | 時間の経過そのもの |
| 22 | 「ここに名を書いた。そして、削った」 | 掻き取り | 最初に欠けた仲間の名 |
| 22 | 「三日のあいだ、剣を抜かなかった」 | 水損 | |
| 23 | 「いまも悔いている」 | 掻き取り | |
| 25 | 「処刑台から生き延びた日にも…」 | 水損 | 記憶の最初と最後が繋がる一行 |
| 25 | 「歩調が変わっていた」 | 滅失 | 読めない |
| 26 | 「それより先を、わたしは聞いていない」 | 滅失 | |
| 27 | 結び | **筆跡が整う** | 削った理由を書く場面だけ、手が落ち着く |

### 筆跡の乱れ

一字ごとに、回転・上下動・墨の濃淡・印圧を与えている。
振幅は物語の進行に従って増える（22丁で 0.35、25丁で 0.70、26丁で 0.85）。
**27 丁だけ 0.40 に戻している。** ここで記録者は取り乱していない。

### 後年の別筆

8・14・23・28 丁に、本文より新しいインク・別の書体・小さい字で書き込みがある。
28 丁のものは蔵書家の手による受入記録の体裁。

## 4. 検収基準（仕様書 10）への自己点検

**1. 「デザインされたもの」ではなく「残されたもの」に見えるか**
　既製テクスチャは一切使っていない。地紋・繊維・毛穴・黄変・損傷・斜線の陰影は
　すべて葉ごとに異なる種から生成しており、**同じ葉は二つとない**。
　装飾効果（ドロップシャドウ・ベベル・外光彩）は使用していない。
　→ ただし、これは当方が判定すべきことではない。**発注者の目で見ていただきたい。**

**2. 損傷の位置と物語の内容が対応しているか** → §3 の表のとおり。

**3. 金が女神関連以外に使われていないか**
　→ 金の指定は本文全体で **6 箇所、3 丁**のみ。
　　5丁（人物一覧のメリディア項＝女神名・称号・契約）、10丁（女神の言葉）、20丁（戒律）。
　　`grep -o '\[\[g|[^]]*\]\]' src/content.mjs` で全数を列挙でき、
　　**6 箇所すべてが女神メリディアに関する記述である。他所での使用はゼロ。**
　　同様に群青は 4 箇所で、すべて第二幕・第三幕（闇の章）の内側。
　　焼けは仕様どおり **1 箇所のみ**。

**4. 日本語本文が、読みやすさを損なわずに写本の質感を持っているか**
　→ 33字詰・行送り 6.2mm（字面の 1.88倍）。禁則処理を実装し、
　　句読点・小書き仮名が行頭に来ない。§5 の 4-3 回答も参照。

**5. 装飾が本文を邪魔していないか**
　→ 装飾頭文字は各幕冒頭のみ・三行取り。細密画は扉のみ。
　　マージナリアは線を細く墨を薄くし、本文より格を落としてある。

## 5. 仕様書 11 のご質問への回答

### 11-1. 和文で写本の質感を出す手法について

**(a) を基本線とし、(b) は使わず、(c) は本文に使わない。**
発注者のご推奨（(a)＋(b)）から一点だけ外しています。理由を述べます。

まず (c) について。**ご指摘のとおりです。** 既製の手書き風和文書体は
「手書きの均質な模倣」であり、一字目と百字目が同じ形をしている。
写本の生々しさは、同じ字が二度と同じ形にならないところから来る。使いませんでした。
唯一の例外が**後年の別筆**で、ここは Klee One を使っています。
用途が「本文とは違う、後の誰かの手」に限定されているので、
別書体であること自体が意味を持ち、既製書体でも嘘になりません。

(a) の実装は、**一字ずつを独立した器に入れ、器ごとに揺らす**という方法を採りました。

- 筆の角度の揺れ（±0.3°〜±1.6°、進行に従い増大）
- 罫線からの浮き沈み（±0.2mm〜±0.9mm）
- **墨継ぎの周期**——14〜36字ごとに墨を継ぎ、直後は濃く、尽きる直前は掠れる
- 稀に生じる墨溜まり（太る字）と掠れ（薄い字）

このうち効いたのは三つ目です。ランダムな濃淡は「ノイズ」にしか見えませんが、
**濃→淡→濃という周期**が入ると、人が筆を運んでいるように見えます。
書き手が墨を継ぐ、という物理が復元されるからです。

(b) を採らなかった理由。手書き画像の混植は、たしかに要所では強い。
ただし本件の損傷は「進行に従って増える」ことが要件です。
画像混植だと、**濃度を連続的に動かせない**。第一幕でほぼ無傷、
終幕で判読困難、というグラデーションを作るには、パラメータで動く仕組みが要りました。
要所に一点だけ実物を混ぜたい、というご要望があれば、後段で追加できます。

書体選定の補足は `納品_使用フォント一覧.md` に記しました。
要点は、**清潔な明朝を後処理で汚すより、はじめから湿っている書体を選ぶほうが確実**、ということです。

### 11-2. 損傷表現の実装方法と、それによる工数・費用の差

見積のご質問ですが、**実物を納めましたので、見積ではなく実測でお答えします。**
（当方は時間単価での受注ではないため、金額での回答は差し控えます。
　代わりに、何が工数を決めるかを申し上げます。）

三つの方法の性質は次のとおりです。

| 方法 | 初期工数 | **修正の工数** | 進行に沿った濃度変化 |
|---|---|---|---|
| 手作業（画面上で一箇所ずつ） | 中 | **箇所数に比例** | 手で調整。整合が崩れやすい |
| 既製テクスチャ | 小 | 小 | **不可能**。かつ仕様 7 で禁止 |
| 実物スキャン | 大（撮影・調達） | 大 | 素材の数だけ必要 |
| **本件で採った手続き的生成** | **大** | **ほぼゼロ** | **パラメータ一つで通る** |

本件が四つ目を採った理由は、費用ではなく**要件**です。
仕様書 5 は「物語が進むほど損傷が増える」「損傷は忘れた出来事の箇所に集中する」
と定めています。これは損傷が**本文の関数**であることを意味します。
関数であるものを手作業で置くと、本文を一行直すたびに損傷を置き直すことになる。

実際の効果を申し上げます。本作業中、**本文は三度書き足しています**
（分量調整と、物語の弧を作るため）。手作業方式なら、そのたびに全丁の損傷を
調整し直す必要がありました。本件では、原稿を書き換えて再生成するだけで済んでいます。

**したがって、修正段階でのご負担はほぼ生じません。**
「この語を削ってほしい」というご指示は、原稿の該当語を `[[s|…]]` で括るだけです。

### 11-3. 細密画を実制作する場合の追加費用と納期

**6 点、すでに制作済みです。**（プロローグ・第一幕・第二幕・幕間・第三幕・終幕）

- 人物の顔は一切描いていません。輪郭・頭巾・逆光・白紙のまま残した面で処理しています。
  終幕の人形の顔は、**塗り残しではなく、はじめから描かれていない**という扱いです。
- 陰影は階調ではなく**斜線**です。滑らかなグラデーションは近代の道具の痕跡なので使っていません。
  斜線は一本ごとに間隔・長さ・角度・濃さを散らしてあります。
  等間隔の平行線は、定規かプロッタの線であって、手の線ではありません。
- 囲み罫だけは揺らしていません。写本の絵の囲みは、実際に定規で引かれるからです。
- 金は 02（神殿）にのみ。群青は 03（コールドハーバー）と 05（門）にのみ。

元データは `out/plates/` にレイヤー保持の SVG で納めました。
**PSD/AI ではありません。** 本件の細密画はラスタでも手描きベジエでもなく、
座標を記述したコードから生成しています。PSD/AI に変換すると
その記述性が失われ、以後の修正が手描きの描き直しになります。
SVG なら Illustrator・Inkscape・Affinity のいずれでもレイヤーとして開き、
GUI で直接編集できます。**座標での修正と GUI での修正の、どちらの経路も残してあります。**
PSD/AI が契約上どうしても必要でしたら、SVG から変換して追納します。

### 11-4. 本仕様で削るべき／足すべきと考える点

**① ノドと小口の比率（4-2）を、逆にすることをご検討ください。** ——最も申し上げたい点です。

仕様書は「ノドを広く、小口を狭く（写本の標準比率）」とされています。
指定に従って組みました（ノド 23mm / 小口 15mm）が、
**中世写本の作図法では、通例これが逆になります。** 小口側が最も広く、
次いで地、ノドが最も狭い。理由は単純で、**人は小口を持って読む**からです。
親指の当たる場所に余白を残す。仕様書 4-6 が「触られた場所（小口、下端の角）だけが濃い」
とされているのは、まさにその作法を前提とした観察です。
**現状は、親指を置く場所が本書で最も狭い。**

指定を上書きはしませんでした。ご判断ください。
逆にする場合、`src/style.mjs` の 2 行の入れ替えで全丁に通ります。

**② 補遺の進行表は、当方で再構成した暫定版です。** ——確認をお願いします。

ご支給の資料では、進行表の行が途中で切れており、全行を読み取れませんでした。
幕構成から再構成した暫定版を入れ、その旨を補遺 30 丁に注記してあります。
**原表をいただければ差し替えます。**

**③ 「彼」の表記について。** ——ご指示に沿った処理の報告です。

主人公の性別が未定とのことでしたので、本文から人称代名詞を外し、
「その人」および称号呼びで通しました。
そのうえで、**その人の名は写本上のすべての箇所で削り取られている**という扱いにしています。
自分を忘れていく人間の記録に、固定された呼称が残っていないほうが、
仕様書 5 の中心と噛み合うと判断しました。
27 丁で記録者が削った理由を述べ、補遺 31 丁で後年の研究者がその事実を確認する、
という二重の枠でこれを支えています。
性別が確定した場合、代名詞を戻すこと自体は原稿の置換で済みますが、
**この仕掛けは崩れます。** どちらを採るかはご判断ください。

**④ 足すべき点があるとすれば、「読めなさ」の総量です。**

現状、判読困難な箇所は終幕に集中して 4 箇所です。仕様書の指定は満たしています。
ただ、実際に通して読むと、**まだ読めすぎる**という感触があります。
記録者が「もう書けなくなっていく」感じを出すなら、
終幕の二丁は、行の脱落（書かれずに空いた行）を入れる余地があります。
これは損傷ではなく**不在**なので、別の設計になります。ご指示があれば加えます。

**⑤ 削るべき点は、見当たりませんでした。**

仕様書 7 の禁止事項は、いずれも妥当だと考えます。特に
「既製の羊皮紙テクスチャをそのまま全面に敷くこと」と
「全面を均一に汚すこと」の二つは、この種の仕事が失敗する典型的な経路です。

## 6. ビルド手順

```bash
cd manuscript
npm install playwright-core          # 描画エンジン
pip install pypdf fonttools          # PDF 仕上げ・フォント処理

node src/build.mjs grounds && node src/render.mjs grounds   # 地紋を葉ごとに焼く
node src/build.mjs        && node src/render.mjs pdf screen && python3 src/finish.py screen
node src/build.mjs print  && node src/render.mjs pdf print  && python3 src/finish.py print
node src/export-plates.mjs                                   # 細密画の元データ
```

`finish.py` は仕上げのたびに検品を回します。
フォントの埋め込み、Type3 への分解、系統外書体への代替、
そして**損傷の下のテキストが検索可能なまま残っているか**を、
実際の語で毎回確認しています。

### 検版

```bash
node src/render.mjs shots screen 19 20 22   # 指定の丁を 300dpi 相当で書き出す
```

## 7. 修正のご指示について

仕様書 9 の修正回数は各段階 2 回とのことですが、
本件の構造上、**次の種類の修正は回数に数えていただかなくて結構です。**

- 本文の加筆・削除・書き換え
- 損傷箇所の追加・移動・削除（原稿に記法を書き足すだけです）
- 損傷の強度、筆跡の乱れ方の調整
- 版面（判型・字詰・行送り・余白）の変更
- 色の調整

いずれも原稿データか定義値の書き換えで通り、全丁に一度で反映されます。
工数が発生するのは、細密画の**構図**の描き直しと、
装飾の**新規**追加のみです。
