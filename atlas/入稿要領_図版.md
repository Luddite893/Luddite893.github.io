## 0　まず、受け渡しの経路について

**会話に添付された画像は、こちらのファイルとして受け取れません。**
画面上では拝見できるのですが、作業機のディスクには降りてきません。
今回添付いただいたアエラとジョラーヴァスクルも、同様に取り込めませんでした。

経路は二つあります。**（一）を推奨します。**

### （一）リポジトリに置いていただく（推奨）

`luddite893/luddite893.github.io` の `atlas/assets/artwork/` 配下に置いてください。

```
atlas/assets/artwork/主図版/companions.png
atlas/assets/artwork/人物図版/companions-1.png
```

置いていただければ、こちらが取り出して組み込みます。
**一点ずつ置ける**ので、49 点が揃うのを待つ必要はありません。

### （二）取得できる URL をお知らせいただく

直接ダウンロードできる URL であれば、こちらから取りに行きます。
一覧をテキストでいただければ、まとめて取得します。

**ただし、こちらの作業機は行き先が制限されています。**
実際に試したところ、次の経路は塞がれていました。

| 経路 | 結果 |
|---|---|
| iCloud 共有リンク（`share.icloud.com`） | **不可**。接続が拒否される |
| 会話への画像添付 | **不可**。画面では拝見できるが、ディスクには降りてこない |
| GitHub（`raw.githubusercontent.com` ほか） | 可 |

したがって、**（一）のリポジトリ経由が確実です。**
`atlas/assets/artwork/` 配下に置いていただければ、こちらが取り出します。
GitHub の画面から直接アップロードできます（Add file → Upload files）。

**別のリポジトリに置かれる場合も、raw の URL をいただければ取りに行きます。**

```sh
python3 src/fetch-artwork.py 主図版   stormcloaks    <URL>
python3 src/fetch-artwork.py 人物図版 stormcloaks-1  <URL>
python3 src/fetch-artwork.py --list 一覧.txt        # 「種別 配置名 URL」を一行一件
```

取り込みの前に三つ検めます。**拡張子は信じません。**

| 検め | 落ちたとき |
|---|---|
| 実体が画像か（先頭の署名を見る） | **置きません。**名指しで報告します |
| 寸法が読めるか | **置きません** |
| 縦横比が規定から 2% 以内か | 置きます。切り抜きで合わせる旨を警告に出します |

### アップロードで気をつけていただきたい一点

GitHub の画面で **「Create new file」から作ると、中身がテキストとして扱われます。**
画像は必ず **「Add file → Upload files」**（またはローカルの `git add`）でお願いします。

置いたあと、GitHub のファイルの画面で**絵が表示されるか**をご確認ください。
「表示できません」「1 lines」のように出る場合、中身が入っていません。
サイズが数十バイトしかないファイルは、まず中身がありません。

## 1　置き場所と名前

| 種別 | 置き場所 | 名前 |
|---|---|---|
| 主図版 | `assets/artwork/主図版/` | `<項の id>.png` |
| 人物図版（甲） | `assets/artwork/人物図版/` | `<項の id>-<掲載順>.png` |

`<項の id>` は本編の内部識別子です。全 58 項の対応表を末尾に付けました。
掲載順は 1 から。同胞団の一人目なら `companions-1.png` です。

**名前が一致した項だけが差し替わります。** 無い項は現行の描画のまま組まれるので、
入稿の途中でも本は常に完成した状態を保ちます。

### 同じ人物が二つの項に出る場合

本書は組織を主語とするので、人物は組織の欄の内側にのみ現れます。
したがって、一人の人物が二つの項に出るときは、**同じ画像を二つの名前で置いてください。**
現在、該当するのは一名のみです。

| 人物 | 置く名前 |
|---|---|
| エリシフ | `holdHaafingar-1.png`（項 50 ソリチュード・一人目）<br>`ninedivines-2.png`（項 30 九大神聖堂・二人目） |

一方だけ置いた場合、もう一方は現行の描画のまま組まれます。誤りではありませんが、
同じ人物が二つの絵で出ることになるので、検分でその旨を申し添えます。

## 2　寸法

| 種別 | 版面での実寸 | 縦横比 | 350dpi での画素 |
|---|---|---|---|
| 主図版 | 174 × 139.2mm | **1.250**（5 : 4） | **2398 × 1918 px** |
| 人物図版 甲 | 62 × 93mm | **0.667**（2 : 3） | **854 × 1281 px** |
| 人物図版 乙 | 34 × 51mm | 0.667 | 469 × 703 px |

縦横比が規定から 2% 以上ずれると検分で名指しします。
比が違う場合は**切り抜きで合わせます**（勝手に縦横比を変えることはしません）。
切り抜き位置にご希望があれば、その旨お知らせください。

**塗り足しは不要です。** 図版は版面の内側に収まるので、裁ち落としません。

## 3　解像度・形式・色

| 項目 | 指定 |
|---|---|
| 解像度 | **350dpi 以上**（上記の画素数以上） |
| 形式 | PNG / JPEG / WebP / TIFF。**PNG を推奨**（線画は PNG のほうが軽く、劣化しない） |
| 色 | グレースケール または RGB。**墨版として扱います** |
| 地 | **白地**でお願いします。透明でも構いませんが、白のほうが確実です |

### 地を白でお願いする理由

二色刷りの体裁を守るためです。支給図版は**墨版**として扱い、
分類色は**その下**に敷きます。合成は乗算なので、図版の白い部分は
分類色と紙の地が透けます。**線には色が乗りません。**

これは初版の規約（納品書 14-3「線に色を乗せた瞬間、二色刷りではなく
着色されたイラストになる」）を、ラスタ図版でも守るための処理です。

図版に灰色の地が敷いてあると、その地に分類色が乗って濁ります。
白地であれば、紙の色がそのまま出ます。

## 4　容量について

実測値を出しました。線画一点の実データで測っています。

| 解像度 | 一点（JPEG q86） | 主図版 49 点 |
|---|---|---|
| 350dpi | 0.74MB | **43MB** |
| 300dpi | 0.58MB | 34MB |
| 250dpi | 0.44MB | 26MB |
| 220dpi | 0.36MB | 21MB |

**ご参考にお送りいただいた水準の図版は、これより密度が高いので 1.5〜2 倍を見込んでください。**
主図版 58 点で 65〜85MB、人物図版 174 点で 55〜75MB になります。

そこで、**二系統を自動で書き出す仕組みにしました。**

- **印刷用**　350dpi のまま。容量に上限を置きません
- **閲覧用**　容量上限 60MB に収まる解像度へ自動で落とす。全点に同じ倍率をかけます

点ごとに解像度を変えないのは、並べたときに一点だけ甘く見えるのを避けるためです。
落とし先の dpi は、実データが揃った時点で機械が決めます。

## 5　入稿後にこちらが行うこと

### 5-1　一括検分（`python3 src/artwork.py inspect`）

改訂指示書 7 節「全点を並べて一度に検分する工程」への実装です。
目視で拾えないものだけを数で出します。

```
【主図版】49 点　版面 174.0 × 139.2mm
  名前                     画素        dpi   縦横比   平均値  最暗%    MB   判定
  companions.png     2398×1918     350   1.250   236.0   4.6%  1.18   可
  ...
  ── 群の平均　明るさ 236.0　調子の幅 54.8
```

判定に出るのは次の五つです。

| 判定 | 意味 |
|---|---|
| 解像度不足 | 300dpi 未満。閲覧用にも足りない |
| 印刷用に不足 | 300〜350dpi。閲覧用は可 |
| 縦横比 | 規定から 2% 以上のずれ |
| **明るさ過多／不足** | **群の平均から離れている**。一点だけ白い／黒い図版を拾う |
| **調子の幅** | 明暗の幅が群と違う。一点だけ眠い／硬い図版を拾う |

**下の二つが要点です。** 一点ずつ承認すると必ずずれるのは、
人間が「前の一枚」としか比べられないからで、
群の平均から何σ離れているかは目では分かりません。ここは機械にやらせます。

### 5-2　二系統の書き出し（`python3 src/artwork.py build`）

印刷用（350dpi・PNG）と閲覧用（自動 dpi・JPEG）を書き出します。

### 5-3　組み込み

版面へ配置し、分類色を下に敷き、図版註を組み、
しおり・内部リンク・索引・頁数を追随させます。

## 6　動作の確認（済）

仕組みが動くことを、実データを通して二度確認しました。

### 6-1　同胞団（初回）

こちらの線画を 350dpi のラスタに焼いて入稿画像に見立てています。

```
埋め込み画像 2 点
  p1  2398×1918  /FlateDecode  /ICCBased  1160KB  → 版面 174mm に対し実効 350dpi
  p2   854×1281  /FlateDecode  /ICCBased   654KB  → 版面  34mm に対し実効 638dpi
```

`out/埋め込み試験_同胞団.pdf`（4 頁・2.5MB）でご確認いただけます。
一頁目の主図版がラスタ、二頁目の人物図版は**三人目だけがラスタで、
一人目と二人目は従来の描画のまま**です。
これが「一点ずつ差し替えられる」ということの実物です。

### 6-2　エリシフ（二回目）

ご指示を受けて、人物図版の差し替えを一点だけ通しました。
**お送りいただいた iCloud のリンクはこちらから開けなかった**ので、
実データの代わりにこちらの描画を入稿画像に見立てています。
実データが届けば、同じ名前で置き換えるだけです。

```
holdHaafingar-1.png  854×1281px  @350dpi  縦横比 0.667  可
ninedivines-2.png    854×1281px  @350dpi  縦横比 0.667  可
```

この工程で一つ直しました。**支給図版は乗算で敷くので白が透け、
こちらの描画は白い地を自分で持っている**——入稿が途中の段では両者が一列に並ぶので、
支給側だけ地が抜けて見えていました。支給側にも同じ白地を敷いています。
全点が揃えば見た目は変わりません。

図版の下部に入稿の控え（ファイル名・画素・dpi）を刷ってあります。
これは校正刷りにだけ出るもので、納品版では消します。
